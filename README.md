# MAX VPN

В экспериментальном транспорте реализованы длительные TCP-сессии через зашифрованные сообщения MAX и локальный HTTP CONNECT адаптер. Проверены на имитации синхронизируемого чата с настоящими TCP-сокетами; реальный MAX для новой схемы и Android VPN остаются непроверенными. [Технические подробности](docs/STATEFUL_TCP.md).

**Серверный прототип развёрнут:** https://max-vpn.mask-0f-darkness.ru/ — отдельный Docker-контейнер на VPS, собственный nginx-vhost и Let's Encrypt. Публичная страница и `/health` работают, но авторизация MAX и VPN-туннель ещё не включены; не вводите коды и пароли MAX на сторонних страницах.

**Экспериментальное приложение для Android и отдельный веб-сайт.** Цель — доступ к обычному интернету при режиме *белых списков* с использованием сообщений **личного аккаунта MAX каждого пользователя**, а не общего аккаунта.

> **Состояние:** прототип интерфейса, **не готовый VPN**. Подключение через MAX ещё не реализовано и не подтверждено. APK не опубликован.

## Что будет работать

Для ПК добавлен **локальный MAX VPN Companion**, повторяющий способ входа из `max-automation/authorize.py`: официальный `web.max.ru` открывается в отдельном окне Microsoft Edge с сохраняемым браузерным профилем на компьютере пользователя. Пароль, SMS-код и cookies не поступают на сайт MAX VPN. В Android добавлен отдельный экран официального MAX Web с локальным WebView-профилем. Это вход в MAX Web, **ещё не подключение VPN-трафика**. Авторизация в приложении не является официальным OAuth MAX, и работа WebView на реальном телефоне пока не проверена.

**Назначение MAX VPN — восстановить доступ к обычному интернету, когда действуют белые списки.** Сервис не предназначен для обхода других ограничений и не гарантирует доступ к заблокированным ресурсам. Сейчас VPN ещё в разработке и подключение недоступно.

## Исходный код

- `android/` — Android-приложение (экран статуса, подключение выключено до готовности транспорта).
- `bridge/` — экспериментальная упаковка бинарных пакетов в сообщения MAX, диагностический адаптер и локальный HTTP CONNECT-прокси на ПК (`python -m bridge.pc_proxy`). Локальный прокси пока НЕ подключён к MAX и не обеспечивает удалённый VPN-доступ. Проверка: `python -m unittest discover -s tests`. Для теста через личный технический аккаунт требуется отдельная локальная установка MAX-автоматизации; аккаунты и сессии в этот репозиторий не включаются.
- `companion/` — локальный HTTP-интерфейс входа через официальный MAX Web, собственный сохраняемый Edge-профиль, адаптер к выбранному тестовому чату и экспериментальный ПК-обработчик.
- `site/` — веб-страница проекта.
- `CHANGELOG.md` — изменения.

**Вход в MAX на ПК:** `pip install -r requirements-pc.txt`, затем двойной щелчок по `start_companion.bat` (Windows), либо `python -m companion.server --open`. Откроется `http://127.0.0.1:18763/`; кнопка «Войти через MAX Web» запускает отдельный Edge на официальном сайте. Профиль браузера хранится в локальной пользовательской папке и не отправляется на сервер. Статический просмотр сайта (`cd site` и `python -m http.server 8080`) доступен, но кнопка авторизации там неактивна. Подробнее: [Авторизация MAX](docs/MAX_LOGIN.md).

Android-проект можно открыть в Android Studio; требуется Android SDK 35 и JDK 17. Это **исходники**, а не готовый установочный файл. Приложение умеет запросить системное разрешение VPN и показать его состояние, но **не устанавливает VPN-соединение** до появления работающего транспорта MAX.

## Экспериментальный транспорт на ПК

**Для ПК и телефона используется один и тот же аккаунт MAX.** Сообщения различаются по роли отправителя (`host` и `mobile`); создавать второй MAX-аккаунт не требуется. Вход в официальный MAX Web добавлен в локальный ПК-компаньон и Android WebView; программное использование личной сессии для VPN-трафика пока не реализовано.

Через технический чат MAX проверены шифрованный запрос, короткое TCP-соединение и обратный ответ. Это отдельный прототип для разработчиков, **не готовый VPN или системный прокси**. Инструкции и ограничения: [PC diagnostic](docs/PC_DIAGNOSTIC.md).

## Приватность

Никогда не отправляйте пароли MAX и SMS-коды в этот проект. Личные сессии, сообщения, ключи и технические конфигурации не публикуются. На текущем этапе сайт не принимает никаких учётных данных.
