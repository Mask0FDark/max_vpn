# Прототип передачи TCP через сообщения MAX

**Выполнено в коде:** клиент и обработчик могут вести одну TCP-сессию через несколько зашифрованных сообщений. Протокол поддерживает `open`, `write`, `read`, `close`. Подключения существуют на отдельном event loop, а браузерная автоматизация MAX остаётся в своём потоке.

## Ограничения

- Это **не полноценный Android VPN**: приложение Android пока не извлекает пакеты из `VpnService` и не использует `SessionClient`.
- Серверный сайт показывает статус и не запрашивает SMS или пароль MAX. Поддерживаемая авторизация личного аккаунта пока отсутствует.
- Обмен по настоящему MAX для **новой многозапросной схемы не проверен**. Есть интеграционный тест через имитацию общей истории сообщений MAX с реальными TCP-сокетами, а также HTTP CONNECT через этот протокол.
- MAX — мессенджер: каждое `write` и `read` требует сообщений, поэтому задержка может быть слишком высокой для TLS/браузера; ограничений скорости и объёма MAX мы не знаем.
- Изоляция: обработчик ограничивает 8 сессий по умолчанию, закрывает простаивающие сессии через 90 секунд. Подключение к localhost и частным IP **запрещено по умолчанию**, чтобы не предоставлять доступ к внутренним сервисам через шлюз.
- Не используйте этот прототип как готовую VPN-службу или публичный неограниченный прокси.

## Раздельный тестовый чат

На ПК-обработчике с *собственным*, предварительно авторизованным профилем Companion можно отдельно включить прототип:

```powershell
$env:MAX_VPN_SHARED_SECRET = '<случайный ключ минимум 32 байта>'
python -m companion.worker --chat-id <ID_вашего_тестового_чата> --sessions
```

На второй конечной точке, открытой **под тем же аккаунтом MAX** (отдельная авторизованная сессия устройства), экспериментальный локальный CONNECT-клиент:

```powershell
$env:MAX_VPN_SHARED_SECRET = '<тот же секрет>'
python -m bridge.connect_over_session --chat-id <ID_вашего_тестового_чата>
```

`127.0.0.1:18765` — адрес локального HTTP CONNECT клиента. Не запускайте одновременно два Playwright-контекста на одном браузерном профиле. Оба участника должны быть видимы в одном разрешённом тестовом чате, который MAX синхронизирует между устройствами. Вышеприведённые команды пока **не проверены на реальной паре устройств**.

Тесты `tests/test_tcp_sessions.py` и `tests/test_connect_over_session.py` подтверждают соединение с локальным эхо-сервером, повторную запись/чтение, правильные направления сообщений и передачу двух порций байтов через локальный HTTP CONNECT.
