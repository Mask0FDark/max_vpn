# Вход через MAX Web — ПК и Android

В проекте используется тот же подход, что в `Mask0FDark/max-automation/authorize.py`: пользователь вручную входит на **официальном** `https://web.max.ru/` через браузер с сохраняемым локальным профилем. Это не OAuth и не вход через API ботов.

## ПК

1. Установите Python 3.12+, Microsoft Edge и зависимости: `python -m pip install -r requirements-pc.txt`.
2. Запустите `start_companion.bat` или `python -m companion.server --open`.
3. Откройте `http://127.0.0.1:18763/` и нажмите «Войти через MAX Web».
4. В отдельном окне Edge войдите в **свой** MAX обычным способом. После появления списка чатов Companion отмечает успешный вход. Закройте окно, когда закончите.

Если драйвер Playwright не запускается, Companion открывает обычное окно Edge напрямую, используя тот же локальный профиль. В этом режиме **автоматическая проверка входа недоступна** — после авторизации убедитесь, что виден список чатов, и закройте окно перед запуском транспорта.

Браузерный профиль хранится отдельно от `D:\MAX` в пользовательском каталоге `%LOCALAPPDATA%\MAXVPN\max-web-profile` (Windows). В репозиторий он не попадает. Локальный сервер прослушивает только `127.0.0.1`, не принимает пароли, SMS, QR-токены или куки. У входа нет публичного API, а POST защищён Origin/CSRF проверками.

Страница на обычном хостинге не может открывать браузер на чужом ПК. Поэтому на публичном сайте кнопка будет недоступна: она включается, только когда сайт открыт с **локального Companion**.

## Использование того же профиля в ПК-обработчике

Вход сохраняет собственный браузерный профиль Companion. После входа **закройте окно авторизации Edge**, чтобы не запускать два браузера с одним профилем одновременно. Затем для отладочной отправки через выбранный вами специальный тестовый чат используйте:

```bat
set MAX_VPN_SHARED_SECRET=<ваша длинная случайная строка, не хранить в Git>
python -m companion.worker --chat-id <ID_вашего_отдельного_тестового_чата>
```

Этот обработчик читает только указанный чат из **того же личного аккаунта MAX**, а не профиль автоматизации `D:\\MAX`. ID чата указывается явно: проект не сканирует личные переписки и ничего не публикует в «Избранное» автоматически. Пока это режим разработки для ограниченных запросов, не полноценный VPN. Для проверки нужен совместимый клиент сообщений на другом устройстве.

## Android

В Android-приложении кнопка «Войти в MAX Web» открывает официальный сайт внутри WebView. Можно войти в **тот же MAX-аккаунт**, что на ПК; другой аккаунт не требуется. Cookies хранятся в частном профиле приложения на самом телефоне. MAX VPN не перехватывает поля пароля и кода и не передаёт cookies на ПК.

**Ограничение:** успешный вход в WebView пока не подключён к службе VPN и не доказывает, что MAX Web доступен в конкретной сети. Некоторые сайты запрещают вход через встроенные браузеры; это необходимо проверить на устройстве.

## Чего этот вход пока НЕ делает

- Не передаёт Android сетевые пакеты через MAX или ПК.
- Не передаёт пользовательские MAX cookies из WebView в Python-процесс.
- Не предоставляет способ логина на публичном сайте без установленного Companion.
- Не гарантирует работу при белых списках.

Ни пароль, ни код подтверждения, ни секреты сессии не должны появляться в issues, логах, диагностике или ответах сайта.
