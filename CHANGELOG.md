# Changelog

## Unreleased

- MAX personal account login: dedicated phone number SMS flow via PyMax Client/SmsAuthFlow on VPS, optional 2FA handled only if MAX asks, session stored in private VPS SQLite, no QR required.
- Android login UI: MAX phone -> SMS code -> optional password, over paired HTTPS owner-only endpoints. No credentials stored by app and server endpoints return no-store responses; unpaired requests return 403.
- Note: Android MAX data-plane still uses a separate MAX WebView session, so the complete single-login full VPN remains unverified and should not be advertised as ready.


- Android 0.4.0-max-alpha: добавлен отдельный MAX WebView-транспорт и MAX VpnService без подмены прямым HTTPS. Прежде чем создавать TUN, выполняется зашифрованный RPC через MAX; если не подтвердился, интернет на телефоне не перехватывается.
- Протокол MX2/AES-GCM совместимый с Android 7+, Python MAX worker поддерживает MX1 и MX2; добавлена обработка DNS UDP на публичном 53 порту.
- 72 Python теста, проверка совместимости AES-GCM Android/Python на Android 7/16; MAX на физическом телефоне и сохранённая VPS-сессия ещё не проверены, поэтому выпуск как готового VPN запрещён.


- Android 0.3.1: после подтверждённой пользовательской привязки и успешных WebSocket `101` по `/relay/check` исправлено затирание сообщения об ошибке запуска и повторные вызовы сервиса во время подключения; состояние включает этап ошибки (`websocket/socks/tun/native`).
- Проверен настоящий запуск TUN+JNI на Android 7 (API24) и Android16 (API36) в автоматизированных эмуляторах.
- Создан постоянный Android signing certificate на ПК вне репозитория; APK 0.3.1 переподписан и проверен с APK v2/v3, чтобы будущие обновления могли использовать одну подпись. С 0.3.0 на 0.3.1 потребуется однократное удаление старой APK из-за прежней сменной debug-подписи.
- Прямой VPS HTTPS-релей на сервере работает. Реальный Android->VPS end-to-end трафик физического телефона всё ещё не подтверждён.


- На настоящем MAX Web проверено внешнее HTTPS-соединение к `example.com:443` через новый протокол: TCP open, TLS с проверкой сертификата и HTTP 200 OK за 10,78 с. Отдельный воспроизводимый скрипт: `tools/probe_live_https.py`.
- Проверено с VPS, что исходящий HTTPS к example.com доступен (HTTP 200). Транспорт телефона и серверная авторизация всё ещё не реализованы.


- Проверен реальный MAX Web с новым протоколом длительных TCP-сессий: `MAX_LIVE_SESSION_OPEN_PASS`, `MAX_LIVE_SESSION_DATA_PASS`, `MAX_LIVE_SESSION_CLOSE_PASS` (5,75 с).
- Проверен настоящий HTTP GET и ответ 200 OK через зашифрованный MAX Web relay: `MAX_LIVE_HTTP_GET_200_PASS` (5,64 с).
- Добавлен воспроизводимый ручной скрипт `tools/probe_live_sessions.py` для разрешённого технического чата; это всё ещё один браузер/аккаунт, а не два независимых устройства.


- Реализован протокол длительных TCP-сессий `open/write/read/close` через шифрованные MAX-сообщения одного аккаунта и `SessionRunner` с отдельным event loop.
- Экспериментальный локальный HTTP CONNECT адаптер и PC Companion `--sessions`; по умолчанию запрещён доступ к частным и локальным IP, ограничены размеры и число сессий.
- Интеграционный тест проверяет несколько передач данных через шифрованный транспорт с общей историей сообщений и TCP echo; отдельный тест проходит HTTP CONNECT.
- На настоящем MAX многозапросный протокол пока не проверен; приложение Android и публичный сервер не подключены к этому data plane.


- Развёрнут отдельный серверный прототип на VPS 135.106.168.43: Docker Compose в `/home/vga/maxvpn`, локальный порт 18764, изолированный Nginx vhost `max-vpn.mask-0f-darkness.ru`.

- Добавлены тесты серверных маршрутов и защита CI от пропущенных зависимостей.


- Добавлен отдельный адаптер `companion/max_chat.py`, который использует локальный профиль MAX VPN после браузерного входа и работает только с явно заданным тестовым чатом.
- Добавлен `python -m companion.worker --chat-id ...` для экспериментальных запросов через личную MAX-сессию, без использования профилей `D:\\MAX`.
- Добавлены тесты выбора чата и работы PC-worker с Companion; общее число локальных тестов — 42.

- В сайте добавлена кнопка «Войти через MAX Web», которая работает только при запуске Companion на 127.0.0.1; локальное API защищено проверкой Origin, Host и CSRF.
- В Android добавлен экран MAX Web (WebView) с отдельной локальной сессией, без перехвата паролей, SMS-кодов или cookies.
- Проверены локальный HTTP API и защита от межсайтовых запросов; это авторизация MAX Web, а не готовый VPN-туннель.
- Добавлен резервный запуск обычного Edge без Playwright при сбое браузерного драйвера; двойное прослушивание локального порта запрещено.
